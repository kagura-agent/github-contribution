## 2. 实现方法

- 沿用 repo 既有机制: `_rocm_props_total_is_carve_out` + `_rocm_classify_unified_memory`（worker.py 的分类器，被 llama.cpp backend 和 training worker 共用 — 修同一处会波及它们，所以不动分类器，只改消费端 inventory）
- 修的是显示路径（About 页 hardware specs 的 gpus 列表数据源），不碰: amd-smi 轮询、training budget（vram_estimation 的 `_apply_unified_memory_correction`）、llama.cpp 后端、`_torch_get_per_device_info`（telemetry）— 这些在真 APU 机器上仍用 GTT 语义

## 3. 边界情况

- **APU-only 主机（Strix Halo 等）**: 单一设备 → hybrid=False → 维持 GTT 行为（有测试钉住）
- **mask 到单设备**: HIP_VISIBLE_DEVICES 只留 dGPU 或只留 iGPU → 集合=1 → hybrid=False → 现状不变
- **分类器异常**: hybrid 检测 try/except 失败 → hybrid=False → 现状不变（保守）
- **props 抓取失败**: 设备跳过（原行为一致）
- **NVIDIA/XPU/MLX**: IS_ROCM=False → hybrid=False → 零影响
- **`_torch_get_per_device_info`（telemetry）**: 不改 — 显示路径与 telemetry 在 hybrid 下会不一致（iGPU 显示 carve-out vs telemetry 显示 GTT），但 issue 只报显示路径；telemetry 面板显示的是 utilization，用户报告的是 About 硬件规格
